# Импорт и экспорт

**Статус:** необязательное расширение.

**Родительский документ:** [Идея продукта](../PRODUCT_CONCEPT.md).

**Обязательная зависимость:** базовый продукт, включая ручную возобновляемую разметку.

**Дополнительное взаимодействие:** [автоматическая разметка](LLM_ANNOTATION.md) может использоваться для разметки импортированных элементов. Она не требуется для импорта и экспорта.

Расширение подчиняется [соглашениям родительского документа](../PRODUCT_CONCEPT.md#10-соглашения-с-расширениями). Здесь определены правила переноса данных; общие правила работы с элементами, разметкой и выборками задаются родительским документом.

## Назначение и варианты переноса

**Экспорт** позволяет передать данные из рабочей области, а **импорт** — принять данные в рабочую область. Рабочая область, из которой передаются данные, называется исходной; область, в которую они поступают, — принимающей.

При экспорте и импорте элемент считается тем же, если его содержание не меняется. Продукт должен распознавать повторный импорт того же элемента.

Расширение должно поддерживать четыре варианта экспорта и импорта:

| Объём переноса | Глоссарий в переносимых данных |
| --- | --- |
| Вся рабочая область | С глоссарием |
| Вся рабочая область | Без глоссария |
| Часть рабочей области | С глоссарием |
| Часть рабочей области | Без глоссария |

При экспорте из текущего узла пользователь выбирает состав экспортируемых элементов:

- Только собственные элементы текущего узла.
- Полную теговую выборку — собственные элементы текущего узла и элементы всех его потомков.

При экспорте части рабочей области с глоссарием пользователь выбирает его состав:

- **Полный глоссарий** — все теги рабочей области, независимо от их использования в экспортируемых элементах.
- **Сокращённый глоссарий** — только теги, использованные в экспортируемых элементах.

При переносе без изменений глоссарий считается тем же. Продукт распознаёт один и тот же глоссарий в разных рабочих областях. Сокращение создаёт самостоятельный глоссарий, отличный от полного исходного.

При экспорте без глоссария теговая разметка элементов сохраняется в экспортируемых данных.

## Названия при повторном импорте

Если название импортируемого элемента отличается от названия того же элемента в принимающей рабочей области, продукт спрашивает пользователя, как поступить с названием. Это правило действует независимо от происхождения названий и состояния разметки элемента.

Пользователь может решить отдельно для каждого элемента, какое название сохранить, либо применить одно решение ко всем различиям названий в текущем импорте: сохранить названия принимающей рабочей области или принять импортируемые.

## Переразметка при импорте

Правила переразметки применяются как при импорте всей рабочей области, так и при импорте её части.

При повторном импорте уже размеченного элемента сохраняется разметка принимающей рабочей области. Это правило действует при переносе с любым глоссарием и без глоссария. Разметка из импортируемых данных её не заменяет и не дополняет.

Повторный импорт уже имеющегося неразмеченного элемента не создаёт копию и не изменяет состояние его разметки. Элемент остаётся в списке неразмеченных; работа с ним продолжается в режиме разметки.

К элементам, которых ещё нет в принимающей рабочей области, применяются следующие правила:

| Условия импорта | Переразметка элементов |
| --- | --- |
| С тем же глоссарием | По желанию пользователя: сохранить исходную разметку или выполнить переразметку. |
| С другим глоссарием | Обязательна для всех новых элементов. |
| Без глоссария | Обязательна для всех новых элементов. |

При импорте с тем же глоссарием без переразметки сохраняется и состояние разметки каждого нового для принимающей области элемента. Неразмеченный элемент остаётся неразмеченным, а элемент с завершённой пустой разметкой — собственным элементом корня.

При импорте сравниваются используемые в данный момент глоссарии; история их изменения не учитывается. При импорте с сокращённым глоссарием в рабочую область с полным исходным глоссарием переразметка всех новых для принимающей области элементов обязательна.

Переразметка выполняется тегами глоссария принимающей рабочей области.

Переразметка набора импортируемых элементов может продолжаться длительное время.

## Взаимодействие с разметкой

Элементы, которым требуется разметка по глоссарию принимающей рабочей области, поступают в предусмотренный базовым продуктом список неразмеченных. Пользователь может размечать их вручную, приостанавливать работу и продолжать позже. Правила завершения разметки отдельных элементов, их участия в выборках, отображения прогресса и доступности исходной разметки определены в родительском документе.

При совместном использовании с расширением автоматической разметки эту работу может выполнять LLM в фоновом режиме. Правила самого импорта, включая сохранение разметки уже имеющихся элементов, от способа последующей разметки не меняются.
