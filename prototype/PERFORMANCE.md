# Диагностика производительности

Дата измерения: 2026-11-11. Числовой порог приёмки не задавался: результаты описывают фактическое поведение прототипа на указанном наборе.

## Среда и способ измерения

- Apple M4, 10 логических ядер, 32 ГБ памяти; macOS, arm64.
- Node.js v25.9.0 для модельных замеров.
- Google Chrome 157.0.8103.39 для браузерного сценария; Vite dev server на `http://127.0.0.1:5173`.
- Backend и внешние API не используются. Браузерный сценарий выполняется в новом Playwright context и изменяет только локальные IndexedDB/localStorage.
- Модельные операции синхронно измеряются через `performance.now()`: один прогрев и девять измерений. В таблице указаны медиана и диапазон минимум–максимум.
- Браузерные значения получены одним прогоном и включают Playwright IPC, React-рендеринг и проверки видимости. Это не чистое время модельных функций.

Воспроизведение:

```bash
npm run diagnostic
npm run test:e2e -- --grep '10 000 элементов'
```

`scripts/diagnostic.ts` выводит JSON со средой, полной частотой каждого из 100 тегов, всеми девятью samples и результатами по узлам. `tests/e2e/diagnostic.spec.ts` выводит отдельный `DIAGNOSTIC_UI`-отчёт и прикладывает его к результату Playwright.

Проверенные узлы:

- корень — 10 000 элементов в выборке;
- заполненный `{тег_001}` — 360 элементов;
- заполненный узел первого элемента `{тег_002, тег_009, тег_068, тег_093}` — 1 элемент;
- незаполненный `{тег_001, тег_002, тег_003}` — 0 элементов.

## Ограничения и наблюдения

- Выборка, построение заполненных узлов и подсчёты переходов сканируют массив в памяти; индексов по тегам нет. Получение переходов повторно считает выборки соседних узлов, поэтому оно доминирует на широких узлах.
- Вычисления синхронно выполняются в основном потоке браузера. На этом наборе интерфейс оставался доступным между действиями, но более крупный или плотный набор может увеличить блокировку основного потока.
- Замеры относятся к одному компьютеру, Chrome и dev server; на слабых устройствах и в других браузерах значения могут отличаться.
- Диагностический набор содержит только короткие тексты, без медиа-Blob. Он проверяет модель и список, но не стоимость больших файлов.
- Порционный DOM ограничивает первоначальный рендер, но модельные операции всё равно обрабатывают весь набор.
